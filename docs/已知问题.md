# 已知问题与限制

按「影响程度」排序。每条都注明是**功能限制**、**环境限制**还是**待改进项**，以及用户可以怎么规避。

## 一、功能限制（设计如此，不打算改）

1. **不翻译代码与界面控件**（设计如此）
   `pre` / `code` / 按钮 / 输入框 / 导航 / 广告 / 图标文字都会被跳过，因此页面上「看起来是英文但没被翻译」的地方，很可能正是这些区域。变量名、函数名、命令行、文件路径、URL、十六进制常量在句子里也会被原样保留——这是刻意的，避免把 `malloc` 译成「内存分配函数」这类破坏性结果。

2. **不打穿 DRM / 付费墙，不下载视频**
   字幕只读取播放器已加载的字幕轨道，不绕过任何访问控制，也不做视频下载。

3. **字幕不可用时会明确失败，不会「编造」字幕**
   当 YouTube 接口受限（如 PoToken 校验）、没有字幕轨道、或页面结构变化时，面板会显示 `字幕不可用` 与具体原因（`NO_TRACKS` / `NO_URL` / `BAD_URL` / `NETWORK` / `HTTP` / `EMPTY`），**不会重试到卡死，也不会用 ASR 伪造内容**。此时可改用 YouTube 自带 CC，或等页面上出现人工字幕后再试。

4. **术语表不保证 100% 命中**
   对非 LLM 引擎（Google / DeepL），术语是在请求前做「英文术语 → 中文术语」的前置替换，长词优先、按词边界匹配，因此：
   - 术语的英文写法必须与页面完全一致（复数、时态、连字符不同就不命中）；
   - 对 LLM 引擎（OpenAI 兼容 / 百炼）术语是写进提示词的「建议」，模型仍可能用别的译法。
   学术/技术写作建议用 LLM 引擎 + 自定义规则。

5. **只翻译「文本块」，不翻译图片里的文字**
   图片、Canvas、视频画面内的英文不在范围内。

6. **PDF、浏览器内置阅读器、`chrome-extension://` 页面不注入**
   内容脚本只匹配 `http/https`；Edge/Chrome 的 PDF 阅读器属于浏览器内部页面，无法注入，这是浏览器安全模型的限制。

## 二、环境限制

7. **Chrome 156 的 `--load-extension` 被忽略（仅影响自动化测试）**
   实测 Chrome 156.0.8078.80 无头模式下即使加了 `--disable-features=DisableLoadExtensionCommandLineSwitch`，扩展依然不会被加载（`chrome://version` 命令行里能看到该参数，但扩展列表为空）。Edge 156.0.4314.58 正常。
   → 影响：`tools/e2e-smoke.mjs` 默认优先用 Edge；**用户在 Chrome 里手工「加载解压缩的扩展」不受影响**，但没有自动化证据，属于「未验证」。

8. **后台标签页里的懒加载翻译会延后**
   为了不把接口打爆，正文按视口懒加载（`IntersectionObserver`）。浏览器不会给完全不可见的标签页派发可见性回调，所以在后台标签里打开英文页面并触发翻译时，段落会先显示「翻译中…」，**切回该标签页后才继续**入队翻译。这是刻意的节流行为，不是卡死。
   → 规避：在该标签页前台触发翻译；或在设置里关闭「懒加载」。

9. **快捷键可能与其他扩展冲突**
   `Alt+Shift+T` / `Alt+Shift+M` / `Alt+Shift+D` 若被占用，可在 `edge://extensions/shortcuts`（Chrome 为 `chrome://extensions/shortcuts`）里改绑。

10. **侧边栏需要 Chromium 116+**
    生词本「在侧边栏打开」依赖 `sidePanel` API；版本过低时会降级为打开独立标签页。

## 三、已知待改进项

11. **免费 Google 端点没有 SLA**
    走的是 `translate.googleapis.com` 的免费单文本接口，官方不承诺稳定性与配额，适合个人使用；批量场景建议配置 DeepL 或 LLM 引擎。长文本会按「6 段 / 1200 字符」自动分批，超长页面请求数会相应增加。

12. **LLM 引擎结果存在波动**
    同一段文本在不同温度/不同模型下译文可能不同；`temperature` 默认 0.2，仍非确定性。此外模型偶尔会漏段或改写占位符——代码已做「长度不匹配则退回逐条重试」与占位符容错还原，但极端情况下仍需人工校对。

13. **缓存不区分「同一文本的不同上下文」**
    缓存键为 `引擎|规则|源语言|目标语言|文本哈希`。同一个句子在技术语境与通用语境下的译文会复用第一次的结果。切换翻译规则（profile）会天然分桶，但不区分更细的上下文。

14. **生词本与历史只存在本地**
    没有账号与云同步；清除浏览器数据、卸载扩展会一起丢失。可在设置里导出 JSON 备份。

15. **大页面首次翻译有一次性成本**
    默认 `maxBlocks: 800`、批量 8、并发 2。含上千段落的页面只会翻译前 800 块（可在「网页翻译参数」里调大），其余部分不会排队——这是为了避免触发接口限流。

16. **没有做像素级视觉回归测试**
    字体、行高、颜色、深色模式等样式项只能肉眼确认；`docs/测试报告.md` 已把「样式视觉回归」列为未验证项。

17. **悬停模式在触屏设备上体验一般**
    没有 hover 的设备需要先点击段落才能看到译文；触屏场景建议用「双语」模式。

## 四、遇到问题时的排查顺序

1. 先在扩展详情页点「Service Worker」看后台是否报错（Edge：`edge://extensions` → 详情 → Service Worker）。
2. 确认对应引擎的密钥状态：设置 → 翻译引擎 → 「密钥状态」应显示「已配置（本次会话）」或「已配置（已持久化）」。
3. 用引擎面板的「测试连接」确认网络与密钥本身可用。
4. 页面没反应时先刷新页面（扩展更新后旧页面里的内容脚本会失效），再点扩展图标重新翻译。
5. 仍未解决：打开 `docs/测试报告.md` 的「复现步骤」跑一遍 `npm run test:e2e`，把输出里的失败步骤发出来。
