| `tests/helpers.js` | 共享常量（占位符样例），非测试文件 |

测试期间发现并修复的两个真实缺陷：

1. `src/common/text.js` 的 `splitSentences` 原正则无法切分中文（中文句号后没有空格），导致长中文段落无法分批 → 改为 `/(?<=[。！？；;])|(?<=[.!?])\s+|\n{2,}/`。
2. `src/background/subtitle-bridge.js` 的 `parseTimedTextXml` 原正则把 `dur` 放在可选组里，导致永远捕获不到时长（`duration` 恒为 0）→ 改为先匹配 `<text ...>...</text>`，再分别从属性串取 `start` / `dur`。

这一轮还暴露并修掉了一个测试脚本自身的缺陷：Chrome 里夹具页可能在扩展装好**之前**就已打开，内容脚本不会补注入，于是「内容脚本通道」失败。现在脚本会先用 `chrome.tabs.getCurrent()` 排除自己所在的设置页，再 reload 其余标签页并重试，实测输出 `tab … · 重载后注入`。

### 4.2 真实 YouTube 视频的字幕链路（`tools/verify-live.mjs`）

```bash
node tools/verify-live.mjs --youtube 8S0FDjFBj8o --headed
```

使用真实视频（TEDx: `8S0FDjFBj8o`）实测，结果：

| 步骤 | 结果 | 实测细节 |
| --- | --- | --- |
| 扩展加载 | ✅ | Service Worker 正常 |
| 视频页与字幕轨道 | ✅ | 标题正常；`player.getPlayerResponse()` 里读到 **28 条字幕轨道**（阿拉伯语/波兰语/德语/法语…） |
| 后台读取字幕轨道 | ✅ | `subtitle.tracks` 返回 28 条轨道，首条 `ar/manual` |
| 后台抓取字幕内容 | ❌ 被站点限制 | `subtitle.cues` 返回 `EMPTY`：`/api/timedtext` 对 `fmt=json3` / 默认 / `fmt=vtt` / `fmt=srv1` 四种请求均返回 **HTTP 200 但响应体为空**（`content-length: 0`），即 YouTube 现在要求请求携带 PoToken |
| 页面播放与原生字幕 | ✅ | 打开 CC 后读到站点原生字幕 `I have nothing.` |
| 页面字幕层 | ✅ | 悬浮层出现两行：`I have nothing.` / `我什么都没有。`，第三行是降级说明 |
| 原生字幕回退翻译 | ✅ | DOM 回退把 `I have nothing.` 译成 `我什么都没有。` |

结论：**字幕接口本身被 YouTube 的 PoToken 策略挡住了（不是本扩展的逻辑错误），扩展按文档要求明确告知原因并降级到「读取站点原生字幕」，且在降级路径上真的译出了双语字幕。**

顺带修掉一个真实缺陷：原来 DOM 回退里用一次性 `setInterval(..., 400)` 检查译文，译文晚到就会永远停在「…」；现在每 400ms 同步一次译文，暂停（视频停住）时也会刷新，实测 40 秒内稳定出现译文行。

## 5. 未验证 / 受限项

以下项目**没有**在本机自动化验证，属于「已知未验证」，请以手工验证为准：

| 项目 | 原因 |
| --- | --- |
| Google Chrome 156（品牌版）命令行加载扩展 | 品牌版 Chrome 已禁用 `--load-extension`：无头与有头模式都试过，加上 `--disable-features=DisableLoadExtensionCommandLineSwitch`、`--enable-unsafe-extension-debugging` 也不生效（扩展列表 0 项、本扩展的 Service Worker 不出现）。**这不影响普通用户**：在 `chrome://extensions` 里手工「加载解压缩的扩展」仍然可用；自动化验证改用 Chrome for Testing 157 完成（见 4.1） |
| Bilibili 真实视频字幕 | 本轮只实测了 YouTube；Bilibili 走的是同一套 `subtitle.tracks` / `subtitle.cues` 协议与 DOM 回退，但未在真实视频上跑过 |
| 字幕接口的「正常可用」路径 | YouTube 已对第三方 timedtext 请求做 PoToken 限制，因此拿不到字幕内容；`parseJson3` / `parseTimedTextXml` 的正确性由单元测试覆盖，但缺少线上样本 |
| DeepL / OpenAI 兼容 / 百炼 真实翻译 | 需要用户自己的 API Key，未在测试中使用任何密钥 |
| 站点规则「自动翻译」在刷新后的持久化 | 逻辑由 `chrome.storage.local` 承载，单元与静态层面已覆盖，但缺少自动化浏览器断言 |
| 悬停模式、字体/颜色等样式项的视觉回归 | 样式只在真实页面肉眼可评估，未做像素级比对 |
| 闪退 / 内存占用等长时运行表现 | 没有做长时间浸泡测试 |
